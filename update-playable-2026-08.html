NeoCraft Development Update #1 — It’s Playable

NeoCraft has moved beyond an idea and become an actual playable client.

Where the project is now

The current build can load the original Alpha 1.1.2_01 resources locally, reach the main menu, create and load worlds, save progress, and run normal gameplay in the browser.

A large portion of the original client is working, including:

  • Original-style world generation, chunk loading, lighting, weather and time
  • Player movement, swimming, jumping, collision and camera controls
  • Mining, block placement, tools, combat and item use
  • Inventory, crafting, furnaces, chests and containers
  • Mobs, animals, dropped items, particles, paintings, boats and minecarts
  • The HUD, menus, chat, options and pause screens
  • First-person hands, held items, fire, water and inside-block overlays
  • Music, sound effects and records when local Alpha resources are supplied
  • Singleplayer world persistence through browser storage

How much of it is actually Rust?

All authored game logic is written in Rust. The current browser build is approximately 96% compiled Rust WebAssembly by file size.

The remaining few percent consists of automatically generated browser-loading code and a very small HTML/CSS shell. There is no handwritten JavaScript gameplay implementation hiding outside the Rust client.

Verification and accuracy

The original Alpha client contained 396 classes considered part of the playable client. Every one of those classes is now accounted for through a Rust implementation, an exact browser replacement, or an explicitly documented unreachable desktop-only path.

The project currently tracks 2,335 original method declarations across those classes. The automated test suite has grown to 2,047 passing tests, covering gameplay behavior, world logic, rendering, networking, saves, input, timing and many of Alpha’s stranger edge cases.

Release builds are also generated twice and compared byte-for-byte before publication. The current optimized game module is just under 2 MB.

How close is NeoCraft to being finished?

I would currently place the first version of NeoCraft at roughly 85–90% complete overall.

The core client implementation itself is further along than that. There is no longer a major gameplay system waiting to be built from scratch. The remaining work is mostly the difficult final stretch: finding behavior that only appears during unusual situations, testing longer sessions, polishing the browser experience and continuing to reduce memory and rendering overhead.

It is already playable, but “playable” and “finished” are not the same thing. A finished build needs to remain reliable across different computers, browsers, worlds, saves and multiplayer servers—not only during controlled tests.

What is left

The largest remaining areas are:

  • Longer singleplayer testing across more seeds, large worlds and unusual saves
  • Real low-end-device testing and further memory, startup and frame-time optimization
  • Wider browser testing, including browser-specific input and WebGL behavior
  • Additional verification of rare entities, block interactions and unusual Java edge cases
  • Final setup, error handling, save-management and resource-loading polish
  • More visual and timing comparisons against the original Alpha client
  • Packaging, documentation and a smoother public testing process

Optimization will continue throughout this work. Recent changes have been removing redundant render state, avoiding per-frame allocations and shrinking the browser build without changing what is drawn.

Release timing

There is not a firm release date yet. The remaining work is much less about building missing foundations and much more about proving that everything already built holds together under real play. I do not want to rush the final part just to call it finished early.

The next updates will focus on testing results, compatibility, performance improvements and any remaining differences found during normal gameplay.
