Before you test

This is a real pre-release build, not a finished public release. Testers should be comfortable encountering bugs and sharing useful details when something goes wrong.

01

Own Java Edition

You need a Microsoft account that owns Minecraft: Java Edition. Never send NeoCraft your password or authentication codes.

02

Supply local resources

NeoCraft does not distribute Minecraft game assets. The test build loads supported Alpha resources supplied locally by the tester.

03

Use a modern browser

Start with an up-to-date desktop browser and working WebGL support. Wider browser and low-end-device testing is part of this phase.

04

Expect change

Builds, setup steps, storage formats, compatibility, and access details may change while testing continues.

Testing priorities

What needs real playtime

  • Creating, loading, saving, and revisiting worlds
  • Long sessions across different seeds and world sizes
  • Movement, mining, crafting, combat, and containers
  • Mobs, weather, lighting, particles, audio, and vehicles
  • Performance on older or lower-powered hardware
  • Browser-specific input, rendering, and WebGL behavior
  • Rare interactions and unusual Alpha edge cases
Protect your worlds

Treat every build as temporary

Test worlds are stored in browser storage. Browser data can be cleared, storage formats can change, and a test build can fail.

  • Do not use the test build as the only copy of anything important.
  • Keep notes about the build you used when reporting save problems.
  • Do not assume a world will remain compatible with every later test.

Keep account information private. Never include passwords, Microsoft authentication codes, session tokens, or private account data in a test report.

Bug reports
